# 开发与恢复

本项目独立保存于GitHub私有仓库 `Lang070114/duxing-class-game`。

## 本地预览

1. 安装Node.js >=22.13、Git。
2. 克隆仓库，进入项目，运行 `npm ci`。
3. 将 `.env.example` 中变量配置到 `.dev.vars`，生成自己的长随机主持口令；不要提交这个文件。
4. `npm run build`，生成本地数据库配置。
5. 按 `drizzle/meta/_journal.json` 顺序应用尚未应用的SQL：

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_overrated_randall.sql
```

6. `npm run dev`，打开命令显示的本机地址。开发数据库与线上数据库分离。

## 保存与恢复

- 每个可运行阶段均保存为提交；已发布版本额外设置标签。
- 查看版本：`git log --oneline --decorate`。
- 查看某个版本：可在GitHub提交或标签页面浏览，不必修改当前文件。
- 要恢复线上：先保存现状，再以选定提交创建恢复分支，验证构建后重新发布对应源码；不要直接强制重置、删除历史或强推。
- 数据库迁移只追加；已应用迁移不修改。代码回撤不会撤销数据库结构和答题数据。
- 主持口令配置于Sites运行时密钥；源码发布包不包含它。本地 `.dev.vars` 也不提交。
- `.openai/hosting.json` 关联原Site，不要重复创建。迁移到新的独立Site时，应先复制不含Site身份与密钥的源码，并重新登记。

## 发布

Sites技能提供构建、源码同步和发布辅助工具。必须先将当前源码推送到Site配置的源码仓库，再用该提交构建并保存发布版本。用户GitHub仓库是额外的版本备份，应保持两边源码一致。只有返回成功的发布地址才可当作上线结果。

## 数据过期

新房间默认有效7天；首次生成报告时将过期时间设为结束后7天。API即时禁止访问到期房间。`POST /api/game`，JSON `{"action":"cleanup"}`，只允许按服务端当前时间删除已到期记录，外部不能指定提前删除的时间或房间。定期清理任务应调用该接口；无到期记录时保持安静。清理入口不提供答题或身份信息。
